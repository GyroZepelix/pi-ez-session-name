# Discovery: Auto-name sessions after first prompt with a configurable cheap model

Work item: `261025-1918-auto-name-sessions-after-first-prompt-with-a-configurable-cheap-model`
Status: Discovering
Created: 2026-10-25
Updated: 2026-10-25

Assurance: low - personal single-user Pi extension; fully reversible (remove package); worst case is a missing or poor session name, and prompt text only goes to a provider the user already uses.

## Objective

Pi does not name sessions automatically. Build a KISS Pi extension (`pi-ez-session-name`) that gives each new interactive session a short display name generated by a configurable cheap model from the first user prompt.

## Desired outcome

After the first prompt of a new session, the session gets a concise 3-8 word name via `pi.setSessionName()`, visible in `/resume`, without delaying or altering the user's prompt.

## Repository and domain context

- Fact: repository contains only the spec/wiki template (`feat: init wiki`); no source, `package.json`, or remote yet.
- Fact: target host is Pi `@earendil-works/pi-coding-agent` 1.4.0 (global bun install).
- Fact: sibling convention `pi-typesafe-bash` uses TypeScript ESM, `pi.extensions` in `package.json`, `peerDependencies` on `@earendil-works/pi-coding-agent`, `node --import tsx --test`, and `tsc --noEmit`.
- Fact: sibling convention `pi-aware` stores config at `<agentDir>/extensions/pi-aware/config.json`.
- Prior art reviewed (not a dependency): `npm:pi-session-name` 0.1.7 (input event, active model, `streamSimple`, reasoning off, 3 retries, sets terminal title).

## Scope

- One extension entry point loaded via `package.json` `pi.extensions`.
- Trigger on the first `input` event of a new session; generate the name in the background (fire-and-forget).
- Model from config file, default `anthropic/claude-haiku-5-5`.
- Warn once per session on failure; no retry.
- Unit tests and type-check.

## Out of scope

- Terminal/tmux title changes (avoid conflict with `pi-aware`).
- Rename/regenerate commands, periodic re-titling, naming from assistant output.
- Naming resumed or forked sessions that already contain user messages.
- Environment-variable or `settings.json` configuration.
- Naming subagent child sessions (they launch with `--no-extensions`).
- Publishing to npm or adding a git remote.

## Confirmed facts and evidence

- Fact: `input` event (`InputEvent { text, images?, source, streamingBehavior? }`) fires in `AgentSession.prompt()` before skill/template expansion; extension commands are handled earlier and do not fire it (`dist/core/agent-session.js` ~1640-1652).
- Fact: raw skill invocations such as `/skill:x args` reach `input` as raw text.
- Fact: `pi.getSessionName()` returns names set via `/name`, `--name`, or `setSessionName`; `setSessionName` appends a `session_info` entry (`dist/core/agent-session.js` 3241).
- Fact: `ctx.modelRegistry.find(provider, id)`, `hasConfiguredAuth(model)`, `streamSimple(model, context, options)`, and `complete(...)` exist (`dist/core/model-registry.d.ts`).
- Fact: `anthropic/claude-haiku-5-5` is listed by `pi --list-models`; it resolves through the built-in `anthropic` provider and needs Anthropic auth in the session (currently supplied via `npm:@gotgenes/pi-anthropic-auth`).
- Fact: `ctx.sessionManager.getBranch()` exposes session entries for detecting prior user messages.

## Constraints and invariants

- Never block, transform, or delay the user's input; handler returns immediately (`continue`).
- Never overwrite an existing name: re-check `getSessionName()` immediately before `setSessionName()`.
- At most one naming attempt per session.
- Treat the prompt as data in the title request (prompt-injection-resistant framing), bound its length, and normalize model output to one short line.
- Do not apply a result to a different session than the one that triggered it (session replacement during generation).
- No runtime dependencies beyond host-provided Pi packages.

## Proposed test seams and acceptance evidence

- Unit tests with fake `pi`/`ctx` objects:
  - names a new session from the first prompt using the configured model;
  - uses `anthropic/claude-haiku-5-5` when config file is absent;
  - skips when already named (`--name`/`/name`) and when the branch has prior user messages;
  - skips empty-text prompts;
  - fires at most once even if more prompts arrive while generating;
  - does not overwrite a name set manually during generation;
  - warns exactly once on missing model, missing auth, provider error, invalid config, or empty output;
  - normalizes quoted/multi-line/punctuated output.
- `tsc --noEmit` passes.
- Manual smoke: `pi -e ./src/index.ts` (or local package install), send a prompt, confirm the name in `/session` or `/resume`.
